# Guía breve para presentar el ejercicio

1. Explicar el diagrama: un documento, lectura por página, contexto recuperado,
   motor intercambiable y un mismo contrato para distintos consumidores.
2. Abrir A: mostrar texto nativo, ocho campos, evidencia y JSON descargable.
3. Abrir B: enseñar OCR, el error conservado en razón social y abstención del
   nombre del notario. No presentar el resultado como perfecto.
4. Abrir C: mostrar fecha original frente a modificación, nuevo representante
   y nuevo capital. Conservar evidencia del antes y después.
5. Revisar una propuesta en el visor: la decisión humana queda separada del
   resultado automático. Mostrar exportación con evidencia y respaldo portable.
6. Enseñar las métricas por campo y explicar por qué tres casos sintéticos
   conocidos no bastan para declarar precisión productiva.
7. Presentar el code review: esquema, evidencia, prompt injection, abstención,
   costos, idempotencia y evolución a cola/servicio autenticado.

Qwen y reglas tienen procedencia distinta. El experimento real de representantes
falló al citar; la referencia se resolvió después por código, con auditoría.
No atribuir esa corrección a un entrenamiento neural ni confundirla con una
prueba independiente. El frontend es una herramienta de revisión adicional al
prototipo de extracción.

8. Abrir INE o comprobante: cargar un archivo, capturar los campos, marcar una
   región de imagen y descargar JSON o ZIP. Esta ficha es manual y está vinculada
   al expediente base; no constituye extracción automática.
